# Langfuse Cloud deployment and smoke verification

The backend's existing LangChain/LangGraph callback sends telemetry to managed
Langfuse Cloud using the deployment's project API keys. The verification session
on 2026-10-02 authenticated to the already configured US Cloud project and
retrieved a synthetic trace generated by the application callback. No new
project, paid plan, or self-hosted Langfuse service was provisioned.

## Deployment configuration

Bind these variables to the backend service through the deployment's environment
and secret manager. Keep the API key values out of source control and frontend
environment variables. Use keys belonging to the project in the selected region.

| Variable | Deployment value |
| --- | --- |
| `LANGFUSE_BASE_URL` | `https://us.cloud.langfuse.com` for the verified US project; `https://cloud.langfuse.com` for an EU project |
| `LANGFUSE_PUBLIC_KEY` | Project public API key from the existing secret binding |
| `LANGFUSE_SECRET_KEY` | Project secret API key from the existing secret binding |
| `LANGFUSE_TRACING_ENABLED` | `true` to enable tracing; `false` to disable the callback |
| `LANGFUSE_TRACING_ENVIRONMENT` | `production` on the production service |
| `LANGFUSE_RELEASE` | Deployed Git revision, for identifying releases in traces |

Set the base URL explicitly: the SDK otherwise defaults to the EU region.
`LANGFUSE_BASE_URL` takes precedence over the legacy `LANGFUSE_HOST` setting.
Restart the backend after changing project credentials or the endpoint so the
SDK's cached client uses the new settings. Without both API keys, the application
returns an empty telemetry callback list.

Install the committed backend requirements. Langfuse **4.15.0** and
`opentelemetry-exporter-otlp-proto-http` **1.44.0** are pinned together because
OpenTelemetry 1.45.0 switched its default HTTP transport to a direct urllib3
pool that ignores inherited proxy variables. The unbounded previous dependency
resolved to Langfuse 4.16.0 / OpenTelemetry 1.45.0: project authentication worked
through HTTPX, while trace export failed. The pinned pair verified both export
and readback through this managed environment's inherited proxy and CA trust.
Preserve proxy and certificate variables supplied by the runtime; keep TLS
verification enabled. Rerun the smoke before upgrading either pinned package.

## Repeatable smoke check

From `textbook-backend`, with the target backend environment already injected:

```sh
python scripts/smoke_langfuse_cloud.py
```

The script requires an explicit supported US/EU Cloud endpoint and both keys.
It uses a local `RunnableLambda` with constant synthetic input/output, a synthetic
user, a unique smoke session, and the application's `create_langfuse_config`.
It never calls an LLM or reads documents, conversations, databases, or caches.
One synthetic trace is retained in the configured Cloud project per successful
run and can be found under `textbook-production-smoke` / `deployment-smoke`.

The script authenticates, invokes the callback, flushes the SDK, and polls the
Cloud trace API to verify the ID, name, user, session, tag, input, output, and
completed chain/span observation. It retries ingestion delays and HTTP 429
within the readback budget, respecting numeric `Retry-After` headers. HTTP 401
or 403 fails immediately. A successful authentication or flush alone does not
count as a verified trace.

Default readback retry time is 45 seconds; `--readback-timeout` accepts up to 60.
`LANGFUSE_SAMPLE_RATE` must be `1` during the smoke so sampling cannot discard
its only trace. Restore the deployment's intended sample rate afterward.
Output contains safe result metadata and the synthetic trace ID; SDK logs,
credential values, and remote response bodies are suppressed. Exit code `0`
means all readback checks passed; exit code `1` means verification failed.

Offline regression checks (no Cloud writes):

```sh
python -m pytest -q tests/test_langfuse_cloud.py
```
